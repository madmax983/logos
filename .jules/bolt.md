**[Optimizing Hot Paths with Allocation Reductions]**
**Learning:** Attempting to eliminate cloning and `collect()` directly on heavy iteration hot paths in `logos-store-pg` and `logos-runtime` often fights the borrow checker or exposes missing `Ord` implementations on custom domain structs. Applying `-D warnings` crate-wide triggers pre-existing pedantic warnings (e.g. `too_many_lines`, `missing_errors_doc`) that block PRs unless the entire file is audited. Using `Vec::with_capacity` paired with `.count()` for line-by-line file reads successfully satisfies performance optimizations without architectural overhauls.
**Action:** Default to vector pre-allocation (`Vec::with_capacity` and `HashSet::with_capacity`) using `.len()` or `.count()` bounds before building complex borrow-checker refactors or changing data structures. Additionally, avoid silencing linters globally unless scoped down effectively via `#[allow(...)]`.
