**[Tangle: Explicit Module Re-exports within logos crates]**
**Tangle:** In `logos-cli`, `logos-tui`, `logos-core`, and `logos-fetch`, internal module implementations were exposed using `pub mod`, violating the architectural principle of strict public APIs and leaking internal details.
**Blueprint:** Updated visibility modifiers from `pub mod` to `pub(crate) mod` within these crates to correctly enforce the Facade pattern. The only exception made was for modules explicitly re-exported (such as those imported by `logos_cli::commands::analytics`), which were properly scoped. Tests and lints were verified using `cargo test` and `cargo clippy`.
**[The Leaky Modules]**
**Tangle:** In `logos-core` and `logos-fetch`, internal module implementations (`domain`, `planning`, `experimental`, `adapters`) were exposed using `pub mod`, violating the architectural principle of strict public APIs and leaking internal details.
**Blueprint:** Updated visibility modifiers from `pub mod` to `pub(crate) mod` within these crates to correctly enforce the Facade pattern and encapsulate domain logic.
**[Dependency Inversion: Presentation Crates Agnostic to Concrete DB Types]**
**Tangle:** The `logos-cli` and `logos-tui` crates, which act as presentation/UI layers, were tightly coupled to the specific `PostgresStore` implementation from `logos-store-pg`. They referenced `AppRuntime::<logos_store_pg::PostgresStore>` explicitly in command arguments, data source traits, and trait implementations, forcing a strong structural dependency on a concrete database driver for generic presentation logic.
**Blueprint:** Refactored the presentation data source traits (e.g., `HomeDataSource`, `BudgetDataSource`, `TxnPoster`, `ReportRuntime`) to be implemented generically over `AppRuntime<S>` where `S: logos_store::LedgerStore`. For static generic methods that don't depend on storage (like `current_month_key_local` or `default_analytics_schema_version`), swapped `PostgresStore` for the lightweight `logos_store::MemoryStore`. This breaks the concrete DB coupling in the application's domain logic traits, properly practicing Dependency Inversion. Added `logos-store` to `logos-tui` dependencies.
